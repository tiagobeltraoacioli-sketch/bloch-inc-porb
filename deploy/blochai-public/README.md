# Public BlochAI hub

`blochai.xyz` is a static product hub linking Graphus, Bloch Space and Bloch Explorer. The canonical Graphus hostname is `bloch-graphus.xyz`. Private prompts, organization data and AML workflows remain in the authenticated `rednblue.space` workspace. Each public portal has a BlochAI widget limited to approved questions about that portal's purpose: Graphus connections/coverage, Space chain observations/freshness, and Explorer blocks/transactions/eUTXO.

Build with `node scripts/build_blochai_public_assets.mjs`, then use this directory's Wrangler configuration. The hub strips incoming authentication headers before serving static assets, sets no cookies and blocks scripts, connections, forms and framing with CSP. It cannot serve assistant JavaScript or accept inference requests. Public information lists configuration targets, not worker uptime.

The three public portals load only the same-origin `/blochai-assistant.js` and `.css` assets. The widget accepts a question ID from a fixed selector; it collects no free text, page contents, wallet identifiers or files. Responses are public portal guidance, not analysis of live records. The existing portal CSP is preserved, and the widget uses no inline script or style.

The public Worker has a dedicated `BLOCHAI_PUBLIC_DB` D1 binding for atomic quotas and hashed, expiring job capabilities only. It has no private database, session, organization or audit bindings. Apply `migrations/0001_public_assistant.sql` to this separate database before deployment. Server secrets `PUBLIC_BLOCHAI_API_TOKEN` and `PUBLIC_BLOCHAI_IP_HASH_KEY` must be installed outside Git. The former is authorized only for the coordinator's `/public/v1/tasks` API. Upstream is pinned to `https://blochai-origin.posternlabs.com`, rejects redirects, and never receives browser cookies or authorization.

The exact task submit route accepts only `{question_id}` and derives the portal from the hostname. Extra fields and query parameters are rejected. Same-origin checks and a required custom client header apply to all API calls. Submit limits are 6/minute and 20/day per daily hashed IP across portals, plus a global 200/day default. No raw IP is stored. Polls require a random capability held only in browser memory; the database stores its digest, portal, task ID and one-hour expiry. The response allowlist excludes tenant, prompt, node and accounting metadata. The browser displays model output as text.

The future GPU contributor program is a roadmap item only. No wallet connection, contribution enrollment, reward calculation, payout or on-chain operation is implemented.

The HTML handler in `../blochai-public-links/` is imported for the three exact HTTPS root routes and `https://bloch.space/app/`. Original HTML requests are forwarded to the same public host. Only a stylesheet and fixed widget are inserted; the widget sits outside application navigation to avoid mobile overflow. Additional routes cover exactly the two widget assets, `/api/blochai/tasks`, and `/api/blochai/tasks/*`; the latter accepts only a 64-character lowercase hex ID. Unrelated application and private API paths retain their original routing. Set `ENABLE_PUBLIC_ASSISTANT=false` to disable inference and show only a product link, or `ENABLE_PUBLIC_LINK=false` to disable HTML insertion. The separate standalone configuration stays disabled and must not be deployed alongside this Worker.

Validation: `node --test tests/test_blochai_public.mjs tests/test_blochai_public_assistant.mjs`; `node scripts/test_blochai_rewriter.mjs`; `node scripts/test_blochai_public_browser.mjs`; `node scripts/test_blochai_assistant_browser.mjs`. API tests use real SQLite with synthetic backend responses. Browser tests verify closed portal questions, capability polling, text rendering, keyboard interaction and desktop/mobile layouts.

The public Worker explicitly uses `global_fetch_private_origin`: its same-zone HTML passthrough must reach the existing Pages origin. Enabling `global_fetch_strictly_public` here loops these requests back into the Worker (Cloudflare error 1019). The inference subrequest is cross-zone, uses a pinned URL and refuses redirects. The separate private portal Worker has no same-zone passthrough and retains its own routing flag. See [Cloudflare compatibility flags](https://developers.cloudflare.com/workers/configuration/compatibility-flags/#global-fetch-strictly-public).

The Space route uses `/app/*` to include its saved `network`/`view` query parameters on reload. The handler still inserts the widget only when pathname is exactly `/app/`; deeper app paths pass through unchanged. Other API and account routes are not covered by this route.
