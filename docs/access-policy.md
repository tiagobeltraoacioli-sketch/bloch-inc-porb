# Graphus public data and delegated score access

The public explorer is planned to display lawful on-chain facts, flow paths, source lineage, and ML detail: feature definitions and values, methods, model versions, validation, uncertainty, drift, and limitations. No trained model or live per-wallet ML output exists yet. The current constellation uses synthetic wallets and events only. Public feature publication needs a data-protection and source-rights review, because a feature can itself disclose or approximate a sensitive inference. A field that exposes a score through a trivial transform is a score and stays private.

**Only the AML score is a delegated product field.** A score grant must be issued explicitly by Bloch Inc or an authorized tenant owner to a named, identity-verified person, with tenant, purpose, wallet or case scope, expiry, lawful-basis record, and audit logging. The person's employer or affiliation may be a government body, bank, DEX, CEX, AML provider, financial-market firm, or wallet provider, but affiliation alone is never a grant. A government request also needs the applicable legal process. A grant can be revoked; a future serving layer must check revocation on each request. No private score endpoint is deployed now.

Public output can be maximally rich in lawful chain facts, graphs, time series, regressions, model cards, source quality, and non-score ML detail. It must not contain raw IP, personal identity records, customer case notes, confidential source claims, private labels, or another tenant's records. IP jurisdiction is only a short-lived, fallible observation from a lawful customer context, not a chain location. Public graph links describe observed transfers, not common ownership or illicit behavior. If public coefficients and wallet features would exactly reconstruct the protected score, the score design must change or the reconstructing field must be treated as score data. The public site must not embed score values, grant secrets, or a call to a private score API.

`service/access.py` is a fail-closed authorization contract and test fixture for this policy. It is not an operational identity provider, revocation service, or API guard. Production requires a separate authenticated service, grant registry, revocation and audit store, source-rights enforcement, rate limits, impact assessment, and human review.
