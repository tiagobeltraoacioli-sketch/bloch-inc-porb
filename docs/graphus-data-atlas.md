# Graphus Data Atlas

The Atlas executes the 84-field contract against bounded public evidence, rather than displaying a static design table. The implementation is in `graphus/assets/atlas_registry.js`, `atlas_engine.js` and `atlas_statistics.js`. The public UI is `graphus/catalog.html`; private governance is `site/atlas.html`. The mounted portal module is generated by `scripts/build_portal_modules.py` and uses the authenticated Graphus gateway.

## Retained time-window comparisons

A calculated pair of time windows can now be saved independently in the private
report library. `kind=window_comparison` accepts either an analysis ID plus its
canonical timeline query, or the ID of an active retained timeline. Both bucket
ranges are explicit, disjoint and chronological, with the same normalized event
search. The server verifies the source and recomputes the child comparison; it does
not accept client-supplied results. Saved-source ownership, expiry and digest are
checked again atomically when committing the new report.

`graphus-atlas-window-comparison-record-1.0.0` wraps canonical source/selection
parameters and the unchanged `graphus-atlas-timeline-comparison-1.0.0` child.
`report_sha256` covers the wrapper without that hash, `comparison_sha256` still
covers the original child, and provenance keeps the original timeline/dataset
hashes. The stored payload has its own byte checksum. The wrapper's hash is the
save request's `expected_report_sha256`; no existing transform version changes.

The read-only viewer preserves both exact event cohorts, typed direction groups,
reference membership and concentration fractions. Its filters affect the CSV
view, while child JSON and complete retained exports preserve the full saved
comparison. Live and retained source candidates are independent; changing a source
invalidates its draft. A lost committed save response can be retried with the same
request UUID. Reports survive deletion of either ancestor, can receive reviews,
join dossiers, and retain existing role, tenant, expiry, deletion and purge rules.
No new source collection, rescoring or on-chain labels are introduced.

Migration `0010_atlas_window_comparison_reports.sql` extends the report kind check
while preserving all four existing kinds, multipart payloads, links and review
history. Storage remains 20 reports per organization, at most 6 MB each, with
1–365 day retention and six new save attempts/minute. Complete oversized reports
fail without truncation. Local migration verification runs with foreign keys on,
populated prior report kinds, multipart data and deliberate rollback failure.

The [unified tool inventory](unified-intelligence.md#public-data-and-central-private-access)
keeps public data research accessible and centralizes score/private-record access.

## Capture, inspect and reproduce

The private portal provides a map icon in its main navigation and an Atlas card on its overview. Saved analyses and individual reference inspectors link directly to `/atlas.html?analysis=…&node=…`; sign-in preserves this destination. The private Atlas can return to the same retained graph and selected reference without collecting new source data.

The private reference workspace lists retained analyses and searches their scored references. Its evidence card shows the exact stored digest, source, coverage and descriptive Red/Blue values. Self-directed events count once in the incident-record total. **Review selected reference** fills its precise subject and starts at `open`; completing the review remains an explicit user action. The grant picker only offers reviewed/resolved records for that exact analysis/reference whose retention covers the requested lifetime. The server repeats these checks at issuance and every delegated read. Reopening a review denies delegated access immediately.

Private records support text, kind, state and selected-reference filters; ten-record pages; matching-record JSON export; and active/open/completed-review/seven-day-expiry counts. The visible record and grant eligibility lists refresh their expiry calculations every 30 seconds and when the tab becomes visible. Expired official results are removed from view, and a failed or superseded lookup cannot leave an earlier snapshot presented as current. Token responses remain available to copy if refreshing the list fails after successful issuance; dismissing or revoking clears their displayed secret.

The private UI pins requests to its loaded organization using the optional `X-Porb-Tenant` header. Authenticated requests with a different current organization return `409 organization_changed_reload` before reads or writes. This does not replace ordinary authentication or scope checks. A context rejection clears the UI's retained data, selection and displayed secret and asks the user to reload. Delayed saved-analysis responses cannot restore a cleared or superseded selection. Failed revision writes preserve the draft for comparison with the latest record.

Choose BTC, ETH, Ethereum USDT/USDC or BLCH. Capture one to eight source pages, extend a capture using its cursor, or open a System Map evidence packet. Limits remain 1,200 references, 4,000 records, 3 MB of dataset bytes and 6 MB of imported packet bytes. Sources are fixed by the existing adapters. Errors retain the last successfully calculated capture; source failures never introduce synthetic observations. Importing while a query is pending cancels that query and prevents a late response from replacing the import.

Reference, event type, exact minimum base units, inclusive UTC start/end and path depth select the calculation. Timestamp-free records are excluded only when a time filter is active; their excluded count remains visible. Filter errors preserve the prior report and its applied parameters. The event ledger has 25-record pages and clickable references. Search, layer, access, result-state and field-inspector links are bookmarkable. The full capture opens in Constellation or Analytics through a consumed, browser-local handoff. The System Map can open its exact evidence packet in Atlas without another chain request.

JSON reports retain the selected exact records, reference metrics, source snapshots, parameters, version and SHA-256 identities. CSV exports the field results with safe quoting and spreadsheet-formula prefix protection. An evidence download retains the original packet, including its digest and any filtered-parent lineage. A matching digest verifies supplied bytes, not the source's identity or consensus correctness.

`analysis_id` hashes a sorted-key JSON object containing the transform version, dataset digest, optional baseline digest, parameters, evaluation time and imported flag. `feature_revision` identifies the transform, input digest and parameter digest. Local holdout evaluations have a separate `report_sha256`; they remain distinct from the chain capture and do not change its analysis identity.

## Review queue and decision history

The private **Review queue** gathers active review and correction records from the organization's existing 200-record inventory. It starts with pending work and provides text, state, assigned-to-me, needs-reviewer, priority and overdue filters with five-item pages. Ordering is human priority, earliest deadline, then oldest creation time and ID. No model chooses the priority. Retained report subjects expose report inspection and links to their investigations; those details require the evidence read scopes and disappear when the report expires or is deleted. Independently retained review text remains governed by its own expiry.

**Assign review** selects a current owner, administrator or analyst, a high/normal/low priority and an optional local-time deadline. The API receives UTC epoch milliseconds. Null clears the reviewer or deadline. Deadlines must fall between creation and current expiry. The directory exposes the first 200 eligible members and discloses truncation; an existing active assignee remains selectable even outside that page. Removed members and viewers are marked unavailable, and their work is counted as needing an active reviewer. Eligibility is checked again inside the write. Assignment does not change roles, approve evidence, infer reviewer independence or extend retention.

Assignment uses the same optimistic revision as record editing. A concurrent assignment/decision admits one write; the loser must reopen the current revision. Record content, revision snapshot and conditional audit are committed atomically. Assignment shares the 30 record writes/minute/organization budget. **Record decision** opens the existing editor with the current revision and state; saving a reviewed/resolved decision removes it from the default pending view. Reopening preserves the previous decisions in retained history and follows the existing score-grant revocation rules. Shortening current retention past an existing deadline is rejected; switching kind to annotation/processing clears workflow fields in the new revision.

**Revision history** is available on every governance record. It shows the recorded actor credential ID, exact text, status, scope, declarations, assignment and expiry for each retained version, newest first in five-version pages. Changed fields are compared only with an immediately preceding retained revision. Unknown migration authors stay unknown; different actor IDs are not evidence of independent review. Export re-reads the current history and returns `porb-atlas-record-history-1.0.0`, explicit completeness/missing counts and `history_sha256` over `JSON.stringify(response without history_sha256)` in returned property order. The checksum verifies export bytes, not the truth or independent attestation of a decision. A changed record or inconsistent latest snapshot fails closed with HTTP 409. Reads are limited to 30/minute/organization, and require only `cases:read`; assignments additionally require `cases:write`.

Migration `0007_atlas_review_workflow.sql` adds workflow columns, the version table/index and transactional snapshot triggers. It preserves each pre-existing current revision as a migration baseline, without fabricating earlier versions. New creates and accepted updates append snapshots. Each record may retain 100 physical versions, including expired ones until administrator purge. Expiry immediately denies historical reads; the active parent is also required. Extending current retention never renews earlier versions. Deletion cascades every version and leaves the audit identity. Purge can remove expired versions of still-active records. Existing dossier bundles include the current workflow fields, while their historical versions have the separate history export.

The browser clears failed queue reads, invalidates delayed history reads when records refresh, clears private state on organization changes, and checks displayed expiry every 30 seconds and when returning to the tab. A confirmed assignment remains reported as saved if refreshing the queue fails. Viewers can inspect history and evidence but receive no assignment or decision controls. JSON downloads are static copies and do not automatically enforce server retention.

## Administrator access audit

The private **Access audit** workspace is available only to current owner/administrator browser sessions. It loads on demand and lists retained `atlas.*` events from the current organization. API keys, analysts, viewers and delegated score tokens cannot use it. The existing organization-context JSON keeps its recent audit summary; the explorer adds exact action, actor credential and recorded-resource filters, inclusive UTC dates and 25-event pages. Action suggestions include records, reports, investigations, reviews, queries, delegation and audit activity. Identifiers remain literal recorded values; no user directory, record body, report payload or deleted evidence is joined into the view.

`GET /api/porb/v1/atlas/audit` accepts optional `start`, `end`, `action`, `actor`, `resource`, `cursor` and `limit` (1–100, default 25). Dates must be valid ISO UTC timestamps. An omitted end uses the snapshot creation time; an omitted start uses 30 days before the resolved end. Windows may span at most 366 days and cannot begin before the Unix epoch. Text filters are exact and case-sensitive. Results are ordered by descending event time and ID. Each new snapshot inserts an `atlas.audit.snapshot` marker into the existing audit table and includes only earlier insertions, excluding new events even when their timestamps are equal or backdated. The internal insertion sequence is never returned. Signed cursors bind the organization, normalized filter hash, marker, expiry and optional last-event position. `snapshot.cursor` returns to the first page; `pagination.next_cursor` advances. Keep the same filters on subsequent requests. Cursors expire after 15 minutes, cannot renew themselves and cannot be replayed across organizations or changed filters. A missing marker fails closed. This is a navigation boundary, not an immutable historical copy; removed or modified database events are not reconstructed.

`GET /api/porb/v1/atlas/audit/export` takes the same filters and the base `snapshot.cursor`, without `limit` or a next-page cursor. Omitting the cursor creates a new snapshot. The server re-reads every retained match across pages and returns `porb-atlas-audit-export-1.0.0`, organization identity, query/window, snapshot metadata, count, events, explicit limitations and `audit_sha256`. Verify SHA-256 over UTF-8 `JSON.stringify(export without audit_sha256)`, preserving returned property and array order. Pretty-printing is not part of that hash. Complete exports are bounded to 1,000 events and 2 MB; HTTP 422 asks for narrower filters rather than returning truncated evidence. Paged responses also reject a result exceeding 2 MB. `complete:true` describes the retained matches within this snapshot/window, not full organization history, immutable logging or independent attestation. CSV downloads come from a fresh verified JSON export, include all its events with quoted, formula-protected text and carry `json_export_sha256` plus organization, snapshot and applied-filter metadata in every event row. An empty CSV contains only its column header; JSON retains the full empty-result context.

Reads allow 30/minute/organization and exports six/minute/organization, in addition to the common authenticated request budget. Successful reads and exports append `atlas.audit.read` and `atlas.audit.export`; those later insertions do not shift the current pages. Responses use private/no-store headers and the existing organization pin. The browser clears superseded queries, failed responses, expired snapshots and changed organization/role context, and verifies the JSON payload hash before offering either download. Returning to a visible tab or the 30-second refresh checks expiry; every server request rechecks it. Downloaded files remain static copies. The routes use the existing audit schema/index and require no migration. They are session-only administration endpoints and are excluded from the PartnerKey OpenAPI contract.

## Implemented calculation families

| Family | Implementation and limits |
| --- | --- |
| Network and asset | Canonical network, pinned native/ERC-20 identity, contract, decimals, public source identity, anchors and captured ranges. Configured RPC credentials are never returned. |
| Raw events | Transaction/event identity, block, observation and acceptance times, exact amounts, typed endpoints, outpoints and receipt/log semantics. Fields refer to the record ledger rather than duplicating every event in each field. |
| Quality and finality | Source-specific finality claims, BTC source-reported confirmation depths and fallback lower bound, missing timestamps/heights, declared omissions, stale-capture flags and baseline block conflicts. A sampled anchor is not a live head or an independent canonicality proof. |
| Wallet and flow | Directed adjacency, distinct neighbors, counts, exact amounts separated by type/direction, high-degree structural caveats and shortest directed paths of at most six hops. UTXO neighbors remain transaction references. |
| Time and behavior | First/last returned block time, disjoint 0–1, 1–24 and 24–168 hour bands, transaction-time gap burstiness, fan-in/out, concentration and strictly chronological account-transfer patterns. |
| Descriptive statistics | UTC daily counts and exact totals, OLS count trend, conservative 95% Student-t slope interval, residuals, R², RMSE, outlier days and same-sample reference cohorts. At most 366 UTC day buckets. |
| Feature transparency | Versioned definitions, units, missing-value rules, inputs, parameters, uncertainty and independent model-evaluation reports. No protected observation scores enter public results. |
| Official sources | Public registry metadata; private UN/UK/EU exact listing-reference lookup with streaming XML, byte digest, parser version and six-hour expiry. Existing OFAC exact-address enrichment remains a separate private workflow. |
| Governance | Organization notes, purpose/lawful-basis/source-rights declarations, expiry, corrections, review status, reviewer assignment, human priorities/deadlines, retained revision history, optimistic updates, deletion and access audit. |
| Delegation | Named recipient and purpose, one reference in one retained analysis, current scoped human review, dedicated token, expiry and immediate revocation. Only descriptive observation scores are deliverable. |

ERC-20 records retain timestamps from their matched block headers, enabling temporal calculations without extra RPC requests. Source-head metadata is retained separately from sampled anchors; finality failure still leaves Bloch head information unavailable.

For amount concentration, denominators remain within the asset, record type and direction. Largest-event/top-ten shares, largest-peer share and peer HHI use exact `BigInt` totals; ratios are truncated to nine decimal places. Zero totals have null shares. Self records are counted once and have a separate direction. Input and output totals are never added to claim transferred UTXO volume.

Temporal paths require strictly increasing block timestamps. Equal-time events cannot establish order. Cycle search is bounded to six hops, 20,000 candidate expansions and 20 returned cycles, with truncation disclosed. Dwell compares each outgoing event with its nearest strictly earlier incoming observation; incoming observations can be reused, so this is not conserved-value matching or coin residence time. Pass-through candidates use a one-hour observation horizon and make no statement about intent. These timestamp heuristics are explicitly inapplicable to UTXO ownership reconstruction.

Daily buckets with no returned records have null counts and null totals. Observed buckets are not represented as complete days. Regression excludes missing days, requires three observed days and uses elapsed UTC days as the predictor. Constant responses have undefined R². The confidence interval assumes independent, homoscedastic residuals and does not account for source sampling. Correlated activity, uneven coverage and post-selection exploration prevent causal or predictive claims.

## Interactive activity timeline

**Activity timeline** is available in the public capture workspace and the private saved-analysis workspace. It reuses the complete loaded packet, including any declared imported parent selection, independently of the field/path/pattern filters. Select an optional exact reference, relative direction, supported event kind, exact minimum base-unit amount and inclusive UTC dates. Incoming, outgoing and self filters require a reference. The reference can be an account, script or transaction where the network semantics support it; it never denotes a known owner. The private workspace initially follows its selected reference, and resetting timeline filters returns to all retained references.

`graphus/assets/atlas_timeline.js` implements `graphus-atlas-timeline-1.0.0`. Minute, hour and day bins are half-open and aligned to the Unix epoch in UTC. Automatic resolution chooses the finest of those intervals that fits within 366 bins. An explicit resolution exceeding that limit fails with HTTP 422 and asks for a coarser interval or narrower range; it is never silently changed. Query endpoints are inclusive, so an event exactly on a bin boundary belongs only to the following bin. Each bin discloses query clipping and its effective bounds. An omitted query bound uses the matching timed sample extent, clamped to the other explicit bound when the selection lies outside the capture. With no valid timed observations and no date bounds, the report retains an unavailable state and no fabricated timeline.

Every eligible event appears once, sorted by time and exact event ID for display reproducibility. Same-time order does not establish execution order. Self events have their own direction and count once. Zero-value and mint/burn observations remain eligible. ETH uses native-value events, USDT/USDC use pinned token transfers, and BTC/BLCH retain their distinct input/output kinds and transaction-reference endpoints. Exact sums use integer arithmetic and remain separate by kind and relative direction; UTXO inputs and outputs are never combined into transfer volume. Duplicate movement identities or supplied outpoints within the same transaction and event kind, conflicting transaction heights and inconsistent block identities/timestamps reject the capture. Missing outpoints are not reconstructed from event positions. Token and UTXO events without a position are excluded. Other exclusions count each event under its first applicable reason, including unsupported kind/endpoint, reference/direction/kind filters, missing/invalid time, amount threshold and UTC window. A bucket without returned events has `observed_events:null`, state `unknown` and no amount groups. No bin claims full source coverage, and BLCH timestamps are not inferred from ingestion time.

Select a bar with the mouse or keyboard, adjust the first/last interval sliders, shift the range, or select all intervals. Search within the selected events by event, transaction or reference text. Twenty-event pages expose exact amounts, timestamps, block identity, endpoints and available outpoint evidence. The histogram keeps the full queried context; selected-range totals, event rows and CSV use the range and text search together. CSV contains every matching event across pages, with the original report/dataset hashes, selected bounds, search criterion, exact amount and bucket time. Quoted fields protect spreadsheet-formula text; an empty selection exports only the column header. **Download complete timeline JSON** preserves every queried bucket/event, filters, exclusions, source snapshots, source coverage, imported provenance and `report_sha256`, independent of the current visual selection. The digest covers UTF-8 `JSON.stringify(report without report_sha256)` in returned property order. It verifies consistency, not source truth. The browser verifies the hash and expected dataset identity before rendering; changed filters/source/organization, failed responses and superseded queries clear the prior result and downloads.

`GET /api/porb/v1/atlas/timeline?analysis=<UUID>` requires `analyses:read` and `scores:read`, a tenant-owned analysis and its verified payload/manifest/dataset hash. Optional parameters are `reference`, `direction` (`all`, `incoming`, `outgoing`, `self`), `kind` (`all` or an asset-supported type), `minimum` (default `"0"`), `interval` (`auto`, `minute`, `hour`, `day`), `start` and `end`. It permits twenty queries/minute/organization, logs `atlas.timeline.read`, honors organization pinning and returns private/no-store JSON. At most 1,200 references, 4,000 records, eight source pages and 8 MB of complete serialized response are allowed. Oversized reports fail without dropping events. Public queries run in the browser. Neither query flow collects additional pages, recalculates scores or automatically persists a report. Private users can separately save the verified full query in **Saved reports**, under the retention and permissions described below. The query endpoint itself requires no migration; retaining timelines requires migration 0009.

## Observed window comparison

**Compare observed time windows** is available inside public, private and retained timelines. Select an earlier range with the timeline chart/sliders, pin it as the baseline, then select a later range. The comparison updates with the selected range; the pinned baseline stays fixed. Both windows must be disjoint, chronological and use the same normalized event search. Their asset, exact-reference, direction, amount and event-kind constraints are inherited from one verified parent query. Graph filters and event-list pagination do not affect the comparison. A changed event search disables the result until the searches agree or a new baseline is pinned. Changing the report, failed source loading, retention expiry or organization clears the comparison with its parent viewer. Superseded asynchronous digests cannot restore cleared results.

`atlas_timeline_compare.js` implements `graphus-atlas-timeline-comparison-1.0.0`. It verifies and copies the original timeline bytes before computing. Each kind/direction group retains exact integer counts, base-unit totals and signed differences. Source and destination endpoints have separate reference distributions, largest event/value shares, count/value concentration and presence in both/baseline-only/comparison-only samples. Concentration is `sum(reference_count²) / event_count²` or `sum(reference_value²) / total_value²`. Fractions retain exact integer numerators/denominators alongside approximations truncated to twelve decimal places. Empty event denominators and zero total value have null concentration/share, not zero. UI percentages and concentration round those approximations for display. Source/destination roles describe the same events independently; they must not be added. Self events count once per role, zero values and mint/burn observations remain eligible, and BTC/BLCH input/output kinds stay separate with transaction/script endpoints and supplied outpoints intact.

The explorer displays window bounds, durations, matched-event bin counts, inherited coverage, group totals and reference comparisons. Unequal durations are explicit; totals are not normalized into rates. Empty bins have unknown coverage, and reference presence applies only to these samples. Neither absence nor a changed share establishes inactivity, a new/disappeared entity, ownership, significance, a structural anomaly or AML risk. No model, threshold, network-wide baseline or chain-history completeness is inferred.

Filter references within either endpoint role and inspect their exact baseline/comparison events. Reference pages contain eight rows and evidence pages ten events. References sort by absolute base-unit difference, then absolute event-count difference, with exact identifiers breaking ties. Paired bars show event shares within each window/group. **Export matching references CSV** includes every matching reference across pages for the displayed group/role/search, exact quantities and share fractions, UTC windows, event search, asset/unit and dataset/timeline/comparison hashes. It quotes and neutralizes spreadsheet-formula text. Empty exports contain only headers. **Download complete window comparison JSON** is independent of reference filters, role/group selection and pagination; it includes both complete selected event sets, all computed groups, query, coverage, provenance and notes. Its `comparison_sha256` hashes UTF-8 `JSON.stringify(report without comparison_sha256)` in returned property order. The original timeline hash remains distinct and unchanged.

The comparison reuses at most 4,000 retained events, 1,200 references and 366 timeline bins; its complete derived JSON is bounded at 12 MB and fails without truncation. There is no new source query, score, endpoint or database write. Pins are local viewer state; saving a timeline retains the original complete query, while the separate comparison JSON preserves the chosen windows and calculations. This feature does not change the existing `kind:comparison` report type for comparing two saved analyses. Saved timeline evidence remains usable for window comparison after the source analysis is deleted, within the timeline's own retention.

## Graph linked to the timeline

**Explore the selected event graph** connects the timeline's range and event search to a directed graph in public captures, private analyses and retained timeline reports. It operates entirely on the verified report already displayed. No additional source query, source-analysis read, scoring or database write is needed. The original timeline version, payload and hashes remain unchanged.

`atlas_timeline_graph.js` implements view version `graphus-atlas-timeline-graph-1.0.0`. Connections group exact `(from, to, kind)` tuples and retain each underlying event ID, first/last observed timestamp and exact base-unit sum. Opposite directions, different event types and self events stay distinct. Self events count once; node degree counts distinct adjacent references and excludes self. Values are descriptive sums within each typed connection, never conserved flow or a combined UTXO input/output volume. Node positions are a deterministic display layout, not geographic coordinates, an embedding, a causal order or a risk measure.

Select a node with the mouse or keyboard, or enter an exact reference from the original timeline, then filter incoming, outgoing or self events and event type. Graph filters apply to its diagram, connection inspector and graph CSV. Direction counts are recalculated at the focused reference; raw event objects keep their original timeline-query direction. The timeline's range/search filters apply before graph filters. A known reference absent from the current time selection produces an empty graph without broadening the range. An unknown reference or invalid filter clears the diagram and disables its export. High-degree selections have a structural warning without identifying a service. Account addresses are circles, scripts are diamonds and transactions are squares. BTC/BLCH preserve transaction endpoints and supplied input/output roles; they do not become inferred direct wallet transfers. Missing timestamps and unknown intervals produce no invented nodes or connections.

Each diagram page shows at most eight connections and sixteen endpoint references; connection cards disclose the total and current page. SVG arrows and cards open the same exact-event inspector, with ten-event pages, full event identities, available outpoint evidence and exact quantities. Changing the timeline's event page preserves graph focus; changing its range or search clears the selected connection and rebuilds the graph. Changing the report/source clears graph filters. Live and saved viewers have independent state, unique input/SVG identities and horizontally scrollable diagrams on small screens. Report expiry, corruption, source loading/failure and organization changes clear their graph content with the parent viewer.

**Export graph events CSV** includes every filtered event across all connection/event pages, or every event of the explicitly selected connection. Its rows carry the graph-view version, original timeline/dataset hashes, asset/unit, selected UTC bounds, timeline search, exact graph reference, graph direction/type, selected connection tuple, event identity, timestamp, exact amount and transaction/block identity. It uses quoted, formula-protected fields. The original report hash identifies the retained calculation; it is not a checksum of the CSV or an independent attestation of the selection. Empty exports contain only their header. **Download complete timeline JSON** still exports the original complete query, regardless of graph selection. Saved governance envelopes and dossier exports also preserve that same original calculation.

## Ordered temporal paths

Both the public capture workspace and the private saved-analysis workspace offer **Temporal paths**. Choose distinct source and destination references, one to six steps, a maximum gap between events and a maximum overall duration (each up to seven days), an exact per-event minimum in base units, an optional inclusive UTC range and up to twenty returned paths. The controls operate independently of the field and comparison filters. The public view uses the entire currently loaded packet, including any already-declared packet selection; it does not fetch another source page. The private view reuses a retained analysis and checks its payload against its database manifest and graph digest before searching. Neither flow recalculates Red/Blue scores.

`graphus/assets/atlas_paths.js` is the shared deterministic engine, version `graphus-atlas-paths-1.0.0`. ETH paths use `native_value`; Ethereum USDT/USDC paths use `erc20_transfer`, with recorded contract metadata checked against the pinned asset registry. Missing legacy token contract metadata is disclosed. Only address-to-address records qualify. BTC and BLCH return `not_applicable`: transaction inputs and outputs do not establish an account-style sender path. The UI disables this search for those assets while retaining their other Atlas features.

Successive events must have strictly increasing valid UTC timestamps **and** block heights. Equal-time, same-block and reverse-height observations cannot establish an ordered path. Search uses simple directed paths with no repeated reference, excludes self events, and does not traverse the zero address as an intermediary. A direct mint/burn endpoint can still appear as an observed reference; it does not identify an actor. Conflicting hashes or valid timestamps at one retained height reject the dataset. Exclusions distinguish unsupported record kinds/endpoints, missing/invalid timestamps, outside-window events, values below the minimum and self events; each excluded record is counted once under its first applicable reason.

Breadth-first traversal returns shorter paths first, with outgoing events sorted by timestamp and exact event ID. Every examined candidate, including a rejected step, consumes the fixed 20,000-expansion budget. If an extra path beyond the requested result count is found, or unexplored candidates hit the expansion cap, the report sets `truncated`, `stop_reason` and `complete_within_query:false`. An exactly full result that exhausts the search remains complete within the query. No returned path is not evidence of absence from the chain, especially when the search is truncated or source history is missing. Per-query bounds remain 1,200 nodes, 4,000 records, eight pages and 6 MB of retained graph bytes.

Selecting a route shows its directed diagram and every step's exact amount, event/transaction identity, block identity, timestamp and gap. Reference degrees of ten or more produce a sample-structure caveat; they do not assign service identities. Step amounts are neither summed into path volume nor treated as conserved value. The report retains input parameters, source snapshots, coverage, exclusions/pruned candidates, dataset SHA-256 and a report SHA-256 over `JSON.stringify(report without report_sha256)`, preserving field/array order. Public imported packets keep their import warning and parent-selection context. JSON export includes all returned paths and provenance. Changing inputs, changing the sample, losing organization context or receiving a failed/superseded response clears the previous result and disables its download.

The private API is `GET /api/porb/v1/atlas/paths?analysis=<UUID>&from=<exact node ID>&to=<exact node ID>`. It requires both `analyses:read` and `scores:read`; ordinary tenant and optional `X-Porb-Tenant` checks apply. Optional parameters are `max_hops` (default 4), `max_paths` (10), `max_gap_seconds` (86400), `max_duration_seconds` (604800), `minimum` (`"0"`), `start` and `end` (ISO UTC). Gap cannot exceed total duration. The endpoint allows twenty searches/minute/organization, logs `atlas.paths.read`, uses private/no-store responses and starts no source requests. No database migration is needed. Public path calculations run within the browser; there is no separate public path-query endpoint.

## Observed temporal patterns

**Observed patterns** is available in the public capture and private saved-analysis workspaces. Select one observed reference and a pattern, inspect its diagram and exact events, and download a checksum-backed JSON report. These controls are independent of the field, path and comparison filters. Public calculations reuse the loaded evidence packet, including its declared parent selection; private calculations verify a retained analysis before searching. Neither flow collects more source pages or recalculates scores.

The shared engine is `graphus/assets/atlas_motifs.js`, version `graphus-atlas-motifs-1.0.0`. Its five query types have explicit, different meanings:

| Pattern | Calculation |
| --- | --- |
| `cycles` | Return to the selected reference in two to six events, with distinct intermediate references. Each step must advance both block timestamp and height; the entire sequence must fit the duration limit. Shorter cycles are returned first. |
| `pass_through` | All qualifying incoming/outgoing event pairs around the reference, with three distinct references, strictly increasing block timestamp and height, and a gap within the duration limit. Events can support several candidates. |
| `fan_in` / `fan_out` | Incoming or outgoing observations within separate half-open UTC bins, aligned to the Unix epoch. A bin must contain the requested number of distinct counterparties. Same-time observations are allowed; the group does not imply event order. |
| `repeated_pair` | At least the requested number of distinct events between the selected reference and one counterparty, in one direction and one UTC bin. Incoming and outgoing events are separate groups. |

The explorer's `pass_through` query enumerates qualifying pairs; the existing `dwell_time` and `pass_through_candidate` field summaries use the nearest earlier incoming observation. They are different disclosed methods and need not return the same count. No method establishes continuity of funds, ownership, intent or validated AML risk. Sequence amounts are never summed. Fan and repeated-pair totals use exact integer arithmetic over the returned directional events only, serialized as decimal strings.

ETH uses native-value observations; Ethereum USDT/USDC use token-transfer observations and check supplied contract metadata against the asset registry. BTC/BLCH return `not_applicable`. Self events and zero-address endpoints are excluded; the zero address cannot be the query reference. Missing/invalid times, unsupported endpoints/kinds, outside-range events and values below the exact minimum are counted as exclusions. Token records also need a log position. Duplicate eligible native transaction IDs or token transaction/log-position identities reject the query, as does one transaction reported at different heights. Shared validation with temporal paths checks node/event identities, block consistency, graph size and any supplied graph digest. Missing legacy token contract metadata remains disclosed.

Queries accept 1–20 results, a duration/bin width of 1–604,800 seconds, an exact nonnegative minimum of up to 78 digits, and optional inclusive ISO UTC start/end bounds. Cycles allow 2–6 steps; fan thresholds allow 2–20 distinct counterparties; repeated pairs allow 2–100 events. Input bounds are 1,200 nodes, 4,000 records, eight source pages and 6 MB of graph bytes. Search stops after 20,000 examined candidates or an additional result beyond the requested count. `truncated`, `stop_reason`, pruned candidate counts and `complete_within_query` disclose incomplete search, including an interrupted search returning zero results. A fully exhausted search with exactly the requested number remains complete within the query. Reports are capped at 8 MB.

UTC bins are half-open and do not search shapes crossing bin boundaries. `window.query_clipped` identifies bins cut by the query's inclusive time bounds; missing source history is a separate limitation. Deterministic result order is structural, not a risk ranking. Neighbor counts use eligible sample events, and ten or more neighbors produces a structural caveat without assigning a service identity.

Selecting a result displays an ordered route or an unordered fan/pair diagram. Fan diagrams show at most twelve counterparties; the searchable, twenty-event-per-page ledger and JSON export retain every event in the returned group. The ledger includes exact endpoints, amount, event/transaction identity, block identity, timestamp and sequence gap where applicable. Reports retain parameters, source snapshots, coverage/exclusions, analysis identity or imported-packet context, dataset SHA-256 and a report SHA-256 over `JSON.stringify(report without report_sha256)`, preserving property/array order. Input/source changes, failed or superseded queries and organization changes clear previous output and disable export.

The private endpoint is `GET /api/porb/v1/atlas/motifs?analysis=<UUID>&reference=<exact node ID>&type=cycles`. It requires `analyses:read` and `scores:read`, checks tenant context, allows twenty searches/minute/organization, logs `atlas.motifs.read` and uses private/no-store responses. Defaults are `max_hops=4`, `max_results=10`, `window_seconds=3600`, `min_counterparties=3`, `min_events=2`, `minimum=0`, with optional `start` and `end`. Public queries run in the browser. Queries do not persist data; private users can separately save the verified result in **Saved reports**, with the retention and permissions described below.

## Compare retained analyses

The private Atlas compares two saved analyses from the same organization without collecting new data or recalculating scores. Select the current analysis in **Saved references**, choose a baseline in **Compare samples**, and run the comparison. An optional exact node ID scopes the report to one reference present in either sample; **Use selected reference** fills the current reference. The reference table can focus a reference observed on either side, including one absent from the current sample.

`GET /api/porb/v1/atlas/compare?baseline=<analysis UUID>&current=<analysis UUID>&reference=<optional exact node ID>` requires `analyses:read` and `scores:read`. It rejects mismatched assets, networks, sources and conflicting retained token contracts. Missing legacy contract metadata remains disclosed. Both payload digests must match the recomputed graph SHA-256 and their database manifests; corruption returns `409 analysis_integrity_failed`. Unknown or unretained organization analyses return 404. No cross-organization IDs or delegated score tokens grant access. Successful reads add an `atlas.compare.read` audit event with both analysis IDs and the report hash.

Events are joined by exact source event ID and classified as unchanged, changed, only in baseline or only in current. Changed fields retain both values: endpoints, kind, exact amount, transaction, position, height, block hash and timestamp. Reference filtering occurs after event identity matching: an event whose endpoint changed away from the chosen reference remains a changed event, while directional amounts and incident counts reflect each side's actual endpoints. Self events count once; distinct neighbor counts exclude self. Amount totals and signed deltas use `BigInt` and are serialized as decimal strings, separately for each record kind and direction. Whole-sample direction is `recorded`; reference scope uses `incoming`, `outgoing` and `self`. UTXO input and output records are never combined into transferred volume.

Overlapping block heights are matched from both retained anchors and event records. Different hashes describe source disagreement, not proof of a chain reorganization or a canonical block. A one-sided record describes observation coverage, not inactivity or deletion. Current-minus-baseline deltas do not imply chronological order; selecting an older current sample produces a note. Source snapshots, collection times, page bounds, termination/cursor metadata, coverage and both dataset hashes are retained. Legacy missing fields stay null; requested cursors and per-page event counts are not reconstructed. Red/Blue scores depend on their own samples and cohorts, so this endpoint does not calculate score trends.

The complete report is bounded to 1,200 nodes, 4,000 records and eight source pages per side, up to 8,000 union event rows and a 16 MB response. Capacity failures return 422; no rows are silently truncated. Comparisons are limited to 20/minute/organization and remain private/no-store. On-demand comparisons are not persisted and require no report table; the optional saved-report workflow below adds separate retention. The report version is `porb-atlas-comparison-1.0.0`; `report_sha256` covers `JSON.stringify(report without report_sha256)`, preserving property and array order. Identical inputs and scope produce the same report hash. Hashes establish consistency of retained bytes, not independent authenticity of the source.

The shared live/saved comparison viewer offers twenty-event pages, category/text/exact-reference filters, expandable before/after fields, twenty-reference pages and a reference search. Exact reference matching considers both endpoints on both retained sides, so changed endpoints remain inspectable under either original or replacement reference. **Show related events** applies this local filter without recalculating counts or directional totals; **Clear reference filter** clears only that filter. **Focus reference** in the live workspace starts a new scoped comparison through the API. Only the live viewer offers this action. Filter state is independent between the live and saved viewers.

Changed fields have a visible label as well as highlighting. Missing field values read **Not recorded**; an absent event side reads **Event not observed**. On mobile, comparison tables become labeled cards. Complete JSON export retains every compared event and its provenance; matching-event CSV includes all matching pages, input analysis IDs, original calculation reference, report hash and the `view_reference`, `view_category` and `view_search` filters. The calculation hash identifies the original comparison, not a newly computed report over the CSV subset. CSV escapes spreadsheet formula prefixes; consumers requiring exact large integers should import amount columns as text or use JSON. Changing a comparison query input, clearing the analysis, switching organization or receiving an error invalidates the previous live result and downloads. Delayed responses cannot restore superseded evidence.

## Saved reports and review

The private **Saved reports** library retains a complete activity-timeline, temporal-path, observed-pattern or sample-comparison report for later review. Run a calculation, choose **Save current timeline**, **Save current paths**, **Save current patterns** or **Save current comparison**, and declare a title, processing purpose, lawful basis, source rights and 1–365 days of retention. The server recomputes the result from the organization's verified retained analyses and compares its hash with the displayed preview. It accepts parameters and the expected digest, never a client-supplied report. Saving collects no fresh chain data and does not rescore references.

Reports retain exact events/amounts, parameters, coverage, versions, dataset identities and source snapshots. Their payloads are independent of the original analyses' 50-run retention. Each organization has 20 storage slots; expired reports count until purged. Each complete serialized payload must fit within 6,000,000 UTF-8 bytes, stored in at most 30 ordered SQL text parts without splitting Unicode surrogate pairs. A timeline, comparison or pattern report can be valid for immediate inspection but exceed this smaller storage limit; saving returns 422 without removing events or partially persisting the report. Empty, unavailable, not-applicable and search-truncated reports retain their original states, limits and completeness flags. Timelines retain every queried bin, exact event, exclusion and unknown-coverage marker; missing timestamps remain missing. Saving a complete serialized report does not imply a complete search or chain history. Six new save attempts per minute per organization are allowed, in addition to the ordinary authenticated request budget.

`POST /api/porb/v1/atlas/reports` requires a UUID `request_id`, `kind` (`timeline`, `paths`, `motifs` or `comparison`), the governance declarations, `retention_days`, `parameters`, and `expected_report_sha256`. Timeline, path and pattern parameters include the source `analysis` UUID and the same typed filters as their respective query endpoints. Comparison parameters are `baseline`, `current` and optional exact `reference`. Metadata, payload parts and create audit are atomic. A retry of identical normalized content with the same extant request ID returns 200 and `duplicate:true`, even when its original analyses are gone. Changed content or an expired existing report returns 409. After deletion or purge the ID can be reused. The browser preserves the request ID when retrying an unchanged draft after an uncertain response, and distinguishes confirmed save success from a failed list refresh. Changed filters, failed queries and source changes invalidate the current calculation save candidate and any draft based on it.

All five library operations require `cases:read`, `analyses:read` and `scores:read`; save and delete additionally require `cases:write`. Tenant scope, organization pinning, private/no-store responses and access audits apply. The list returns active metadata and capacity counts. Read/export reassemble every ordered part, check the stored UTF-8 byte count and `payload_sha256`, then independently check the inner `report_sha256`, asset and version. Manifest kind, query parameters and summary must also agree with the verified calculation. `payload_sha256` hashes `JSON.stringify(report)` in stored property order; `report_sha256` hashes the calculation with that inner hash omitted. Missing/expired reports return 404 and corruption returns 409. Digests verify consistency of retained evidence, not source authenticity or canonical chain truth. The export wrapper includes metadata, integrity status and the complete calculation; it is not a Graphus source-packet import.

The library offers text/kind filters, ten-report pages, source/parameter inspection, complete JSON downloads and separate review creation. **Review report** starts an open governance record with the exact subject `atlas-report:<report UUID>` and copies the report's declared purpose, basis and rights. It never records a decision automatically or authorizes a score grant. Immutable report content is corrected through a separate correction/review record. Review retention is independent; deleting or purging a report leaves its audit and separately retained records intact. A delete requires the retained payload digest and a second UI click to confirm.

**Inspect report** uses the stored calculation after server verification, including after the source analyses are gone. All four report kinds have interactive inspection without new collection or calculation:

- Timelines reopen with their original UTC bins, keyboard/bar/range navigation, event search, exact grouped amounts and twenty-event pages. CSV includes every matching event across pages with original digests and selection criteria. Query controls are hidden; local range/search changes never alter the saved calculation. Empty windows and captures without timestamps remain distinguishable. Saving from a filtered view retains the entire queried timeline, not just the visible selection.

- Paths reopen with a route picker, ordered diagram, exact per-step event/block identities, original coverage and search limits. Query controls are hidden. Empty results, truncated searches and unsupported UTXO queries retain their distinct explanations.
- Patterns reopen with their original diagram, pattern picker and searchable/paginated event ledger. Cards identify pattern type, count, eligible events and query completeness; library text search also matches the exact reference. Query controls are hidden.
- Comparisons reopen with side-by-side event differences, reference presence/neighborhood counts and the same local filters and pagination as the live viewer. No source-analysis navigation or recalculation is needed. Filtered CSV retains its view criteria; original summary amounts, counts, query scope and report hash stay unchanged.

Each viewer downloads its complete original calculation JSON, while the library's **Export JSON** re-reads and downloads the governance/integrity envelope. Lazy **Complete saved calculation** inspection remains available for every kind. Expiry, deletion and organization changes clear the entire viewer with the rest of the saved report. Failed integrity checks clear previously inspected content, and a delayed response cannot replace a newer inspection.

Expiry denies server reads immediately; visible expired cards/details are cleared every 30 seconds and when the tab becomes visible. The library envelope export repeats server verification and expiry checks; the viewer's raw JSON/CSV exports use the already verified displayed calculation. Organization changes clear candidates, drafts, saved details and lists, and delayed responses cannot restore another organization's content. A viewer can inspect and export but cannot save, delete or create reviews. An administrator's existing **Purge expired records** action now also physically deletes expired reports and their payload parts. Migration `0005_atlas_reports.sql` adds the two tables and indexes without altering existing analyses, scores or governance records.

## Investigation dossiers

**Investigation dossiers** connects the Atlas library to existing organization investigations. Create an investigation in Atlas or open one from the portal's **Atlas report dossier** link. Select a saved timeline, path, pattern or comparison report and attach it using its payload digest. Inspect its original verified contents, start a separate human review, filter its links by report kind, and close or reopen the investigation. Deep links use `/atlas.html?case=<UUID>` and survive the sign-in handoff. Closing a case does not approve its reports or reviews. The portal's original export is explicitly named **Export reference snapshots JSON**; it remains separate from the Atlas report dossier.

Migration `0006_atlas_case_reports.sql` adds only an attachment table and index. Links store the investigation/report identities, the verified attachment digest, actor and time. They do not copy payloads or extend report retention. At most 20 links may belong to one case, including unavailable reports; the existing 100-case organization limit still applies. Attachment, audit and case timestamp update are atomic. A repeated case/report attachment reuses its existing link and does not duplicate its create audit. A report's exact payload and inner calculation hashes must verify before attachment. New links and removals require an open case and `cases:write` in addition to all read scopes. Removal requires the link ID and exact attachment digest and leaves the report intact. Deleting the investigation cascades its links. Closing it preserves reads and exports.

When a report expires or is deleted, its attachment identity/digest remains until detached or the case is deleted. Its title, payload and associated governance content are excluded from the dossier. The separate Atlas record library still applies each record's own retention. The dossier lists an unavailable placeholder so an incomplete evidence set is not silently presented as complete. Expiry clears displayed contents on the existing 30-second/visibility check; deletions recognized by the report library clear the linked card immediately. Private context changes clear selections, drafts and dossier content, and delayed responses cannot restore them.

`GET /api/porb/v1/atlas/cases/{id}` returns the tenant-owned investigation, ordered report links, active report metadata and exact-subject governance records. This metadata view does not claim payload verification. `POST /{id}/reports` accepts `{report_id,payload_sha256}` and allows 30 attempts/minute/organization. `DELETE /{id}/reports/{link_id}` accepts `{payload_sha256}`. All routes require `cases:read`, `analyses:read` and `scores:read`; mutation routes additionally require `cases:write`. Viewers can inspect and export only. All results are private/no-store; successful reads and mutations are audited.

`GET /api/porb/v1/atlas/cases/{id}/export` verifies every retained report and exports its complete calculation with current unexpired annotations, processing declarations, corrections and human reviews. Report states remain explicit; no decision is inferred from a case's status. Expired/deleted reports remain placeholders and set `complete:false`; this flag describes only the attached set, never full chain coverage. A corrupted report or mismatched attachment digest blocks the entire export with 409. The case, links, report metadata and record revisions/expiry are read again after payload verification; changes return `409 case_changed_retry` instead of mixing snapshots.

Exports are limited to six/minute/organization and 12,000,000 UTF-8 bytes. A metadata preflight bounds payload reads; final serialization also enforces the cap. Oversized dossiers return 422 without truncation; use individual report exports or smaller investigations. The returned `porb-atlas-case-bundle-1.0.0` envelope includes generation time, the earliest included report/record expiry, complete/unavailable counts and `bundle_sha256` over `JSON.stringify(bundle without bundle_sha256)`, preserving property order. Inner report/payload hashes remain present. Downloads neither refresh themselves nor enforce server retention. Reference snapshots and their scores are not included in this Atlas bundle; their separate portal export and count are disclosed. No new source collection, score computation or source truth claim is introduced.

## Model evaluation

The browser-local evaluator accepts at most 2 MB / 10,000 rows. The downloadable example is explicitly synthetic. Inputs require `schema_version`, `label_origin`, `model_version`, ISO UTC `training_cutoff`, declared `training_entities`, binary labeled `rows`, and `review_capacity`. Optional `threshold` defaults to 0.5; optional `baseline_probabilities` supports distribution comparison.

Every row has unique `id`, `entity`, ISO UTC `observed_at`, probability in [0,1], and label 0/1. Holdout entities must not occur in the declared training entities, and every timestamp must be later than the cutoff. The report includes precision at review capacity with Wilson interval and tie disclosure, confusion counts, recall/FPR with intervals, Brier score, ten-bin reliability/ECE and optional smoothed baseline-quantile PSI. Missing classes produce null denominators. Repeated holdout entities are counted and the row-level interval dependence limitation is disclosed. Input declarations and labels remain unverified; `release_approved` is always false.

Pinning a source capture compares record identities, changed values and overlapping block hashes against another capture from the same asset/network/source. Neighbor-count PSI compares complete captured reference sets before UI filters. It is a descriptive shift, not calibrated predictive accuracy. Filtered packets can be analyzed but cannot serve as continuation or comparison baselines.
